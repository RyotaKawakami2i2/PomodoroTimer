# 基本設計書

対象プロジェクト: ポモドーロタイマーアプリ（ブラウザ動作・タイマー／メモ・タスク／音楽プレイヤー統合）

前提となる要件・判断根拠は [`requirements.md`](../requirements.md) を参照。

## 1. 概要・目的

- ブラウザ上で動作するポモドーロタイマーアプリケーション。タイマー機能に加え、テキストベースのメモ帳・タスク管理、YouTubeリンクによる音楽プレイヤーを1画面にまとめ、画面の隅に常時表示できる小型ウィジェットとして使うことを目的とする。
- ログイン機能は持たない。データはすべて利用者のブラウザ内にのみ保存し、外部サーバーへは一切送信しない（音楽再生時にYouTubeへアクセスする点のみ例外）。

## 2. 対象環境

| 項目 | 内容 |
|---|---|
| 推奨ブラウザ | Google Chrome / Microsoft Edge（最新版） |
| 推奨理由 | 画面の隅への常時ポップアップ表示に **Document Picture-in-Picture API** を使用するため（Chrome/Edge系のみ対応） |
| 対象OS | Windows / macOS / Linux(Ubuntu) 問わず、上記ブラウザが動作する環境 |
| 非対応ブラウザでの挙動 | Firefox・SafariはDocument PiP API非対応のため「常時最前面の小窓表示」機能のみ利用不可。通常のブラウザタブ/ウィンドウ内でのアプリ利用（タイマー・メモ・タスク・音楽再生）は問題なく可能（機能検出により自動的に縮退表示） |
| 画面解像度 | 指定なし。アプリ自体が幅200px程度の縦長1カラムレイアウトで完結するため解像度非依存 |

## 3. 採用技術・言語

- **HTML5 / CSS3 / JavaScript (ES2020+)** のみを使用する。
- フロントエンドフレームワーク（React, Vue等）・ビルドツール（Webpack, Vite等）は使用しない。
- 採用理由:
  1. 「最初にHTML/CSS/JSをすべて渡し、以降はやり取りしない」という要件に最も忠実であり、単一の静的ファイル群としてそのまま配布・利用できる。
  2. ビルド工程を挟まないことで、ファイルを開くだけでそのまま動作する状態を保てる。
  3. 機能規模的にフレームワークを要するほどの複雑さがない。
- JavaScriptは `<script type="module">` によるES Modules形式でファイルを機能単位に分割する。
- 外部ライブラリは **YouTube IFrame Player API**（`https://www.youtube.com/iframe_api`）のみを、音楽再生機能を使う時に動的に読み込む。それ以外の外部ライブラリ・CDN・Webフォント等は使用しない。

## 4. システム構成

バックエンドサーバー・API・データベースサーバーは存在しない。フロントエンドのみで完結する構成とする。

```
┌───────────────────────────────────────────┐
│                利用者のブラウザ                 │
│                                             │
│  ┌─────────────────────────────────────┐  │
│  │   Pomodoroアプリ (HTML/CSS/JS)         │  │
│  │   - タイマー機能                        │  │
│  │   - メモ・タスク管理                     │  │
│  │   - 音楽プレイヤー(UI・再生制御)          │  │
│  └───────────────┬─────────────────────┘  │
│                  │ 保存 / 読込                │
│  ┌───────────────▼─────────────────────┐  │
│  │   IndexedDB（ブラウザ内ストレージ）        │  │
│  └─────────────────────────────────────┘  │
└──────────────────┬──────────────────────────┘
                    │ 音楽再生機能を使う時のみ
                    ▼
          ┌───────────────────────┐
          │  YouTube                │
          │ (IFrame Player API)     │
          └───────────────────────┘
```

- 静的ファイル（HTML/CSS/JS）は初回配信（ローカルファイルとして開く、または任意の静的ホスティング経由）されるのみで、以降のページ内動作はすべてクライアント側で完結する。

## 6. データ永続化方針

- ストレージには `localStorage` ではなく **IndexedDB** を採用する（保存容量が大きく、ブラウザの自動削除対象になりにくいため）。
- ページ初回起動時に `navigator.storage.persist()` を呼び出し、ブラウザへ永続化ストレージを要求する（対応ブラウザでは容量逼迫時の自動削除対象から除外されやすくなる）。
- データスキーマ概要（IndexedDBオブジェクトストア案）:

| ストア名 | 内容 | 主なフィールド |
|---|---|---|
| `settings` | タイマー時間などの設定 | `workMinutes`, `breakMinutes` |
| `memos` | メモ（複数件） | `id`, `title`, `body`, `order`, `updatedAt` |
| `tasks` | タスク（複数件） | `id`, `text`, `done`, `order`, `updatedAt` |
| `playlist` | 音楽プレイリスト | `id`, `videoId`, `title`, `order` |

- バックアップの書き出し/読み込みは、上記全ストアの内容を1つのJSONファイルにシリアライズ/デシリアライズすることで実現する（詳細は [`detail/04_settings_backup.md`](detail/04_settings_backup.md) を参照）。

## 7. 外部連携方針

通信が発生するのは以下2パターンのみとする。

1. アプリの初回読み込み時（HTML/CSS/JSファイルの配信）
2. 音楽再生機能を使う時（YouTube IFrame Player APIの読み込み・動画再生）

上記以外の場面（タイマー動作中、メモ・タスクの編集・保存、バックアップの書き出し/読み込み）では一切の外部通信を行わない。YouTube IFrame Player APIのスクリプトはアプリ起動時に先読みせず、ユーザーが実際に音楽再生UIを操作したタイミングで動的に読み込むことで、完全オフライン状態を可能な限り維持する。

## 8. 非機能要件

| 分類 | 方針 |
|---|---|
| オフライン対応 | 音楽再生を使わない限り、ネットワーク接続なしでも全機能が利用可能であることを基本方針とする |
| プライバシー | データは利用者のブラウザ内にのみ保存され、開発者・第三者を含む外部への送信は一切行わない |
| セキュリティ | 保存データは暗号化しない（`requirements.md` 6章で確定済み）。同一PC・同一ユーザーアカウント内での閲覧リスクは利用者が許容する前提とする |
| パフォーマンス | タイマーの秒単位カウントに数百ms以上のずれを生じさせない。画面操作の体感応答は100ms以内を目標とする |
| ブラウザ制限事項 | Document PiP機能はChrome/Edgeのみ対応。非対応ブラウザでは通常のウィンドウ/タブ表示に自動的に縮退する |

## 9. 用語集

- **Document Picture-in-Picture API (Document PiP)**: Webページの一部を「常に最前面」の小さな別ウィンドウとして切り出して表示できるブラウザAPI（Chrome/Edge対応）。
- **IndexedDB**: ブラウザに搭載された、比較的大容量のデータをクライアント側だけで保存できるデータベース機能。
- **YouTube IFrame Player API**: 自分のWebページ内にYouTubeの動画プレイヤーを埋め込み、JavaScriptから再生/停止等を制御できる公式API。
- **navigator.storage.persist()**: ブラウザに対して「このサイトのデータを容量逼迫時にも自動削除しないでほしい」と要求するWeb標準API。
